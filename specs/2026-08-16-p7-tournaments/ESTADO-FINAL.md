# ESTADO FINAL — P7: Tournaments

> Drilled from an empty cluster on 2026-08-18. **Ten of ten deployables are real**: the last
> placeholder is gone, and every context in `docs/design/02-bounded-contexts.md` is running code.
> Four `bot --tournament` processes register, are drawn into rooms, play best-of-three matches and
> produce a champion — with the bracket readable from analytics and a placement rating that moves
> without touching Elo.

## What shipped

- **`tournament/`** — the orchestrator (Kotlin), tenth and last service to become real. The
  aggregate is a pure `decide`/`evolve` pair mirroring the Uno engine; its own event log and outbox
  commit in one transaction; the `tournament-saga` consumer group turns a room's verdict into a
  round's progress; a reconciler finishes what a crash interrupts.
- **room-gameplay** — `roomType` is honoured (it had been accepted and ignored since P3),
  `POST /internal/rooms` provisions a room with everyone seated and game 1 dealt in one
  transaction, and the engine plays a best-of-three: `matchScores`, auto-start of games 2 and 3,
  `MatchCompleted` with `advancingPlayers`, and §6.8.3's tiebreaks.
- **The internal door got a lock** — `X-Internal-Token` across the whole `/internal` prefix, timer
  worker included. `SYSTEM_AUTH` was never a credential; it checked a naming convention.
- **outbox-relay** — source-agnostic (four env knobs, defaults byte-identical to room-gameplay's)
  and running **twice**, one Deployment per producer from one image and one digest pin.
- **ranking** — the placement rating from `TournamentCompleted`, as a separate rating in its own
  column and history table; **both** rating writes made concurrency-safe.
- **analytics** — the bracket read model P6 deliberately left unbuilt, projected by the existing
  consumer group into the schema it already owned, and served by `analytics-api`.
- **Gateway + CLI** — six new routes behind the one door, `tournament register|status|bracket`, and
  `bot --tournament`. One command plays a whole event.
- **Contracts** — two more producer/consumer pairs, each sample generated by the producer that
  publishes it.

## Evidence

`validation.md` carries the transcripts. The short version: ten of ten from empty, a champion
through the CLI, the bracket read back, placement **1024/976** with Elo untouched at **1000/0**,
`grep -c seed` **0** on the new topic, **1,587 events replayed and deduped with every projection
byte-identical**, and the casual gate playing a full game with wild, draw, uno and challenge all
observed.

## What the drills caught that nothing else did

**A registration that lost every race reported success.** `submit` exhausted its optimistic-
concurrency attempts and returned `Ok`. Four bots were each told they had registered; three
registrations existed; the threshold was never reached and nothing anywhere said why. Confidently
wrong, which is worse than an error — the same shape as P6's `rating` bug, one layer in. Now a
distinct `Contended` outcome, a `409`, and a client that retries.

**`ModuleNotFoundError: No module named 'placement'`.** ranking crash-looped because the Dockerfile
lists modules by name and P7 added one without adding it there. Every test passed: a test imports
from a directory, a container imports from an image. All three Python services now have a test that
compares the two.

**Four clients opened four tournaments.** P3's two-process lesson in a new place — and the code
carried a comment claiming a convergence it did not implement. Every client now takes the lowest
open id: the same rule on every side, no coordinator.

**A client that assumed game one.** `autoplay` hardcoded `/games/1`, so when game 2 of a match
started, game 1 stopped being readable and the bot waited for a completion it could no longer see.
Correct until P7, because a casual room only ever has one game. The bot also treated a room as
finished after a single game, so a best-of-three could never complete.

**The timer worker 401'd on every tick — but only on a rolling upgrade.** Its pod started 37 seconds
before the secret gained `INTERNAL_TOKEN`, and `envFrom` resolves at pod creation: a Deployment does
not restart when a Secret changes. On the from-empty cluster it did not happen, because
`secrets-staging` syncs at wave −1. **A fresh cluster cannot show this class of defect**, which is
the mirror image of the P6 lesson and worth remembering in both directions.

## Decisions worth carrying forward

- **The room decides who advances.** Every game of a match is the same people in the same room, so
  the scores are the room's own state (§3.2.2). The tournament asks for rooms and records verdicts;
  it never re-derives one.
- **Provisioning is synchronous, so a round is only announced once its rooms exist.** The
  idempotency key is the round's own coordinates, which is what makes a crash between provisioning
  and the append recoverable rather than a duplicate bracket.
- **An unset shared token closes the internal routes.** A security control that defaults to off is
  not a control.
- **No NetworkPolicy was shipped.** Neither kindnet nor the EKS VPC CNI enforces one without extra
  setup, so it would be enforced nowhere this project runs while becoming load-bearing and untested
  the first time one did.
- **Ranking's replica count is now a capacity decision, not a data-loss bug** — and the comment that
  used to warn about it says so.
- **Analytics stays the scalable contrast**: every bracket write is an atomic upsert of a fact an
  event stated, never a counter this service keeps.

## Known gaps, deliberate

- **No Round Kickoff Workers** (§3.2's sharded surge pool): at a threshold of four it is a pool of
  one. R3's rule — the scale story is told with the architecture's numbers.
- **No `tournament.room-creation` topic** (E1) and **no admin role** for `CreateTournament`:
  identity has no roles and P7 does not invent one.
- **No stale-room detector or compensating read** (§7.4.2): the timer worker is the recovery path
  that exists, and it is what unstuck four tournaments at once when it came back.
- **One replica per consumer**, still. F6 removed the correctness barrier in ranking; nothing turns
  the number up.
- **The ~75 duplicated lines between the two Python consumers stay** (D6) — revisited deliberately,
  not inherited: P7's own consumer is Kotlin, so the duplication did not grow, and the kaniko
  build-context trade that made sharing expensive has not changed.
